# шаурматч_ — платформа обратного ИТ-найма на подтверждённых навыках

Хакатон «Лидеры цифровой трансформации 2026», спецтрек Федерации спортивного программирования (ФСП).

Кандидат не откликается вслепую. Его категория (**специализация × грейд**) определяется **опросом, выбором грейда и тестом**, который невозможно «слить», — метод **«ШАУРМА»**. Работодатель описывает потребность, получает подборку из подходящих категорий с объяснением и **сам выходит на контакт** с приглашением, где **зарплата «от–до» указана обязательно**. Контакты кандидата открываются только после того, как он принял приглашение.

## Быстрый старт

```bash
cp .env.example .env          # при необходимости поменяйте порт и PUBLIC_URL
docker compose up -d --build
```

Откройте **http://localhost** (порт задаётся `HTTP_PORT`). При первом старте база заполняется демо-данными: 360 синтетических кандидатов прошли ту же механику ШАУРМА, есть 5 компаний, потребности, вакансии и приглашения.

| Демо-аккаунт (пароль `shaurma2026`) | Что показать |
|---|---|
| `new@shaurmatch.demo` | Путь кандидата с нуля: опрос → тест → категория |
| `alexey@shaurmatch.demo` | Кандидат BE·SEN с историей ФСП, входящие приглашения |
| `maria@shaurmatch.demo` | Кандидат FE·MID **без истории ФСП** |
| `employer@shaurmatch.demo` | Работодатель «ТехноЛаб»: подбор, карта рынка, воронка, «Слепая дегустация» |

Можно и зарегистрироваться самому: в демо-режиме (`DEMO_MODE=true`) ссылка подтверждения email показывается на экране. Все письма также видны в Mailpit: `http://localhost:8025`.

## Сквозной сценарий (ТЗ, п. 3.3)
1. **Кандидат:** регистрация по email → подтверждение → опрос (отрасль, специализация, стек) → выбор грейда → адаптивный тест → категория (например `BE·MID`). Если грейд не подтвердился, можно сразу пройти тест на уровень ниже. Смена грейда — не чаще раза в 90 дней. Можно добавить дополнительные категории (по тесту в другой специализации), например `BE·SEN` + `DS·MID` — у демо-кандидата `alexey@shaurmatch.demo`.
2. **Работодатель:** «Подбор» → описать потребность словами → рецепт навыков → рекомендованные категории и ранжированная подборка с объяснением → «Пригласить» (вилка обязательна).
3. **Кандидат:** «Приглашения» → принять или отклонить с причиной. После принятия контакты открыты работодателю.
4. **Регулярные задачи:** раз в неделю система адресно предлагает кандидату задачу — сначала от работодателя его категории («Слепая дегустация»), а если таких нет, «Свежую начинку» по «остывшему» или слабому навыку. Решить или предложить подход; проверка автоматическая.
   **Профиль:** ФИО и места работы видны работодателю по умолчанию (контакты — только после согласия), стек подтверждается заданиями теста, разбор PDF-резюме извлекает роли и места работы, а своя модель подсказывает специализацию.
5. **«Маринад»:** ответы кандидатов калибруют тест, правки рецептов учат языковую модель, ответы на приглашения и отметки «наняли» учат подбор (P(подойдёт) × P(примет)). Всё видно на `/marinade`.
6. **Дополнительно:** вакансии и отклики, регулярные задачи («Слепая дегустация»), «Честный ценник» против фиктивных вакансий, PDF-профиль, режимы доступности, мобильная версия.

## Структура репозитория
```
engine/      ШАУРМА-движок (Python, FastAPI): шаблоны, мутации, адаптивный тест, Glicko-2, рецепты, матчинг, антислив, валидация,
             «Маринад» (app/learn: калибровка, детектор дрейфа, ранжировщик, языковая модель; training/: симуляция года)
backend/     REST API (Node.js, Express, TypeScript, PostgreSQL), OpenAPI, авторизация, Keycloak (OIDC)
frontend/    Веб-приложение (React, TypeScript, Vite), дизайн-система в src/styles.css
fsp-mock/    Мок-сервис реестра ФСП (структура данных предложена командой)
keycloak/    Realm «fsp» для входа через ФСП ID (необязательный профиль)
docs/        Документация, отчёт валидации, openapi.json, брендбук и логотипы (docs/brand)
scripts/     Сборка PDF-документации
```

## Локальная разработка без Docker
```bash
docker run -d --name proof-pg -e POSTGRES_USER=proof -e POSTGRES_PASSWORD=proof -e POSTGRES_DB=proof -p 5433:5432 postgres:16-alpine
cd engine   && pip install -r requirements.txt && uvicorn app.main:app --port 8001
cd fsp-mock && npm i && node server.js
cd backend  && npm i && npm run seed && npm run dev      # http://localhost:8080/api/docs
cd frontend && npm i && npm run dev                      # http://localhost:5173
cd engine   && python -m validation.simulate --n 2000    # пересчитать отчёт валидации
cd engine   && python -m training.marinate --bake         # «год жизни платформы» + запечь модели «Маринада»
```

Код открыт и не обфусцирован. Компании и демо-профили вымышлены.
